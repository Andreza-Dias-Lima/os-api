API Ordem de Serviço

Arquitetura resiliente com FastAPI, PostgreSQL, Idempotência, Outbox Pattern e Observabilidade.

Problema e Objetivos

  • Evitar duplicidade
  • Garantir consistência
  • Publicar eventos com confiabilidade
  • Rastreabilidade ponta a ponta

Arquitetura

Cliente → API → Service → Repository → PostgreSQL → Outbox → Worker

Estratégia de Banco

PostgreSQL por suporte ACID, transações e consistência.

  • ordens_servico
  • idempotency_keys
  • outbox_events

CAP Theorem

Estratégia CP: Consistency

Preferimos consistência a disponibilidade em cenários extremos.

Idempotência

Mesma chave → mesma resposta → nenhuma duplicidade operacional.

Outbox Pattern

Ordem e evento persistidos na mesma transação garantindo consistência.

Observabilidade

  • Correlation ID
  • Logs estruturados
  • Rastreabilidade do Worker

Monitoramento

  • Prometheus
  • Grafana
  • OpenTelemetry
  • Loki
  • Tempo
